# ТЕХНИЧЕСКИЕ РЕШЕНИЯ Messages

Справочный файл (ветка `notes`, в `main` не попадает). Меняется только когда этап меняет устройство системы. Статус, порядок работ, решения владельца, правила процесса и бэклог лежат в docs/PROJECT-CONTEXT.md. Закрытая часть (деплой, чек-лист аудита, PIN) в файле проекта Claude.
Обновлено: 18 ноября 2026 (после PR #64, №29a).

## РЕШЕНИЯ
- Стек: TypeScript, React + Vite, Node.js + WebSocket, PostgreSQL (Neon), хостинг Render. Монорепо pnpm: apps/web, apps/server, packages/crypto.
- Ключи: сид BIP-39 → HKDF → отдельные ключи: личность (Ed25519, публичный = адрес), шифрование сообщений (X25519), шифрование истории (симметричный). Сообщения: libsodium (X25519 + XChaCha20-Poly1305); копия для отправителя (senderCopy) шифруется ключом истории.
- Вход на сервер без пароля: challenge-response (подпись случайной строки ключом личности).
- Сессия на клиенте: IndexedDB. Необязательный PIN: Argon2id (64 MiB, 3 итерации, соль 16 байт) + XChaCha20-Poly1305, blob v1; PIN от 6 символов, NFKC; паузы после неверного PIN: 5-я ошибка 5 мин, 6-я 15 мин, 7-я и далее 60 мин; сбой KDF не считается ошибкой PIN; серверный токен при PIN шифруется отдельным ключом HKDF (метка messages/v1/pin-server-session).
- Формат сообщения v2: внутри шифртекста {v:2, id (16 случайных байт), type:"text", text, sentAt, rev?}; в AAD отправитель, получатель, их ключи и id; копия отправителя привязана к автору, собеседнику, id и clientMsgId. Правка = замена содержимого той же строки (rev 1..100). Дедупликация по (автор, id), остаётся меньший seq. Неизвестный type молча пропускается (в том числе старые edit, delete_request, delete_answer). v1 читается без защиты от повтора. После изменения формата или протокола просим всех обновить страницу (F5).
- Правка и удаление своих сообщений (на месте, без очереди, нужна связь): PUT /messages/:id {ciphertext, senderCopy} → 204 (404 чужая или нет, 409 уже стёртая); DELETE /messages/:id без тела и без Content-Type → 204 (повтор тоже 204): сервер стирает шифртекст и копию, строка остаётся с признаком deleted. У собеседника и на других устройствах автора заглушка, подряд идущие заглушки одного автора сворачиваются в одну строку. Чужое сообщение удалить нельзя, срока давности нет. В «Избранном» тоже можно, тексты без слова «собеседник».
- Очистка и удаление чата: «Очистить чат» = DELETE /conversations/:peerId (только у себя, на всех своих устройствах, ответ {clearedBeforeSeq}); «Удалить чат» = POST /conversations/:peerId/erase с телом {} (стирает все мои строки этого чата и очищает у себя, ответ {erased, clearedBeforeSeq}). Собеседнику приходит рамка messages_erased {from,to,upToSeq,changeSeq} (его входящие строки от автора с seq не выше upToSeq становятся заглушками); своим устройствам приходит conversation_cleared {peerId, clearedBeforeSeq, hidden}. При ошибке или без связи чат не меняется, ошибка видна в окне подтверждения. Проект: docs/DELETE-OWN.md.
- Список чатов (№27d1): conversation_clears.hidden (старые строки true, новые по умолчанию false); «Очистить» ставит hidden=false, «Удалить чат» hidden=true. GET /conversations возвращает {conversations, cleared}: чат с видимыми сообщениями (cleared:false) ИЛИ пустой очищенный чат с hidden=false (cleared:true, lastSeq = clearedBeforeSeq, lastCreatedAt = время очистки, lastChangeSeq "0", без null); в cleared у записей есть hidden. Новое сообщение само возвращает чат.
- Изменения доходят рамками WebSocket message_updated, message_deleted, messages_erased. У каждой строки change_seq; GET /conversations отдаёт lastChangeSeq, GET /history/:peerId?changedAfter=n догружает изменённые строки (запас 100). Стёртая строка отдаётся с deleted:true и пустым шифртекстом.
- Синхронизация отправленных между устройствами (№27e): сервер шлёт остальным сокетам автора рамку own_message {id, to, clientMsgId, senderCopy, createdAt, seq}; клиент расшифровывает senderCopy ключом истории.
- Сервер хранит: публичные ключи, шифртекст, метаданные (кто/кому/когда, статусы, seq, change_seq, факт правки или стирания, отметки очистки conversation_clears). Остальное API: GET /history/:peerId (страницами), GET/PUT /contacts (зашифрованная книга контактов peerId→имя, версия и защита от перезаписи, до 1000 записей). Статусы: отправляется / отправлено / доставлено / прочитано; онлайн-статусы; heartbeat (ping 25 с, таймаут 10 с, только видимая вкладка).
- Клиент: ядро apps/web/src/lib/chat-controller.ts, интерфейс apps/web/src/main.tsx, тексты i18n.ts, стили style.css, e2e apps/web/e2e/chat.spec.ts (+ pin.spec.ts). Ошибки показываются над полем ввода или в окне подтверждения. Язык: авто + выбор, ключ localStorage messages-lang.
- Клиент, список и очистка (№27d2a): Chat.cleared + isClearedChat; «Очистить» оставляет чат пустым («Чат очищен», в окне «Вы очистили чат»); «Удалить чат» убирает чат и закрывает окно; applyConversationClear(peerId, seq, hidden, fromList): при загрузке списка чаты не создаются и не удаляются, состав определяет reconcileConversations; fetchHistory ставит hasMore=false на пороге очистки; «Избранное» всегда первая строка (withSavedChat в main.tsx).
- Клиент, корзинка (№27d2b, №29a): строка списка = div.chat-row с кнопкой chat-item и соседней кнопкой chat-row-delete. Корзинка видна: на компьютере через 1000 мс удержания мыши (CHAT_ROW_DELETE_HOVER_DELAY_MS, hoverRevealPeerId, класс hover-reveal), на касании после долгого нажатия 500 мс (lib/long-press.ts, класс reveal), при клавиатурном фокусе (:focus-visible; :focus-within не использовать). Подтверждение chatConfirmation = {action, peerId, origin: "menu"|"list"}, не зависит от activePeer.
- Клиент, шапка и меню (№29, №29a): шапка открытого чата: одна кнопка contact-name-trigger (имя, хвост ID из 10 символов, статус, ✎) запускает правку имени; меню «⋯» (chat-menu): «Скопировать ID» (первым, кроме «Избранного»), «Очистить чат», «Удалить чат». Копирование в буфер только через copyText (lib/clipboard.ts: navigator.clipboard, запасной вариант скрытое поле + execCommand; не для сид-фразы и секретов). Подтверждение копирования на самой кнопке меню («ID скопирован» 1600 мс, затем меню закрывается), сбой показывается блоком id-copy-failed с полным ID; так же копирование своего ID в профиле.

## ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ (приняты осознанно)
- Потеря сид-фразы = потеря аккаунта, восстановления нет.
- Сервер видит метаданные (кто кому пишет и когда, факт правки, очистки или стирания), но не содержимое.
- Нет forward secrecy (утечка сид-фразы открывает и старую переписку).
- Код сайта приходит с сервера; смягчается открытым исходным кодом.
- Бесплатный Render засыпает через 15 минут, пробуждение около минуты.
- Паузы PIN обходятся при доступе к F12 и копии данных (защищает длина PIN); разблокированную сессию PIN не защищает.
- Правка и удаление работают на сервере: он заменяет или стирает шифртекст, и любой клиент (в том числе изменённый), запросивший историю после этого, получит новое состояние. Но сервер не может отозвать то, что собеседник уже получил: прочитанное, скопированное, сфотографированное и сохранённое изменённым клиентом (он может проигнорировать рамку удаления).
- Правка и удаление требуют связи у автора (очереди нет). Вкладка, пропустившая рамку, или клиент без обновления (F5) показывают старое состояние или «не удалось расшифровать» до перезагрузки.
- Резервные копии базы у хостинга могут жить ограниченное время.
