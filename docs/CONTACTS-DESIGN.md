# ПРОЕКТ «КОНТАКТЫ» (утверждён владельцем 24 ноября 2026, с дополнениями владельца)

Файл ветки `notes`, в `main` не попадает. Статус и порядок работ: docs/PROJECT-CONTEXT.md.

## Что делаем
Пункт «Контакты» в меню профиля открывает список ВСЕХ сохранённых контактов, независимо от того, есть ли с ними чат. Тап по контакту открывает карточку контакта (как в Telegram). Сервер и миграции не меняются; меняется формат зашифрованной книги (описание контакта, обратно совместимо).

Карточка контакта (этап «Контакты»): имя (можно изменить), ID (копирование), «Моё описание» (до 200 символов: кто это и зачем добавлен), кнопки «Написать» и «Убрать из контактов». Кнопки и блоки, которых ещё нет («Позвонить», «О себе»), НЕ показываем как нерабочие: они появятся вместе с функциями (профиль, звонки).

## Что есть в основе (проверено по коду 24 ноября, main после PR #82)
- Книга контактов: словарь «ID → имя». Имя обязательно (1–64 символа без управляющих), максимум 1000 записей. Книга шифруется на устройстве ключом истории, сервер хранит один шифрблок и номер версии (при расхождении версий 409). Лимит блока на сервере 256 КиБ после декодирования.
- ChatController: saveContactName (пустое имя = убрать запись), loadContacts, state.contacts, contactsError; openChat (проверяет ключ собеседника через getVerifiedPeerKey); contactLabel.
- Сегодня контакт задаётся только в шапке чата или в форме «Новый чат»; списка контактов нет. «Удалить чат» книгу не трогает.
- Старый недочёт: при расхождении версий saveContactName склеивает книги, и запись, удалённая на другом устройстве, может вернуться. Чинится в №34a.

## Решения
1. Контакт и чат независимы. «Удалить чат» и «Очистить чат» контакт НЕ трогают (решение владельца 24 ноября); «Убрать из контактов» не трогает чат и сообщения.
2. Описание контакта (идея владельца): приватная заметка «кто это, зачем добавил», до 200 символов (по символам, не по байтам), одна строка, без управляющих символов. Видна только владельцу аккаунта, собеседнику не передаётся. Предел можно поднять позже без изменения формата.
3. Формат книги: { v: 1, contacts: { id: имя }, notes: { id: описание } }; поле notes пишется только если не пусто, поэтому старые книги читаются как есть, а книга без описаний не отличается от прежней. Описание есть только у контакта с именем; убрали контакт, ушло и описание. Размер: открытый текст книги не больше 200 КиБ (запас под лимит сервера 256 КиБ); при превышении отдельная понятная ошибка «книга заполнена». Старая вкладка без обновления (F5) при сохранении может потерять описания: как всегда после смены формата, просим обновить страницу.
4. Добавить по ID (экран «Контакты»): ID, имя (обязательно), описание (необязательно). Порядок: формат ID → свой ID отклоняется («Избранное» контактом не бывает) → контакт уже есть → проверка ключа собеседника как при создании чата → сохранение. Чат не создаётся и не открывается.
5. Переименовать и править описание: на экране «Контакты» пустое имя не удаляет контакт, а даёт ошибку «Введите имя» (удаление только отдельной кнопкой). Пустое описание = описание убрано. Поведение шапки чата не меняется.
6. Убрать из контактов: удаляется запись и описание; окно подтверждения с пояснением «Чат и сообщения останутся».
7. Одинаковые имена у разных ID разрешены; в списке рядом всегда хвост ID (10 символов).
8. Слияние при расхождении версий: заново применяется ОДНО действие пользователя (имя, описание, добавить, убрать) к свежей книге с сервера, а не склейка двух книг.
9. Офлайн: книга живёт только в памяти (на диск не кэшируем). Пока книга не загружена или не расшифрована, правка запрещена, ошибка видна на экране. Все изменения требуют связи; ошибка видна в форме или строке.
10. Вид: внутри экрана home вместо списка чатов открывается список контактов с «Назад» (без новых маршрутов, window.history.state не трогаем). Сортировка по имени без учёта регистра. Поиска нет (бэклог). Признак «открыт экран контактов» и черновики сбрасываются в трёх путях: выход confirmLogout, вылет onDeviceRevoked, новый вход enter() (урок №28f); при F5 экран не восстанавливается.
11. Шапка чата открывает карточку контакта (как в Telegram): отдельным малым ТЗ №34d после экрана (меняет существующее поведение и e2e шапки).

## Как защищаем
- Имена, описания и ID контактов шифруются на устройстве (ключ истории, отдельная метка HKDF), сервер видит только шифрблок, версию и его размер. Описание собеседнику не уходит.
- Добавляя контакт, клиент проверяет подпись публичных ключей собеседника (verifyUserKeys), как при создании чата.
- Тексты выводятся как обычный текст; управляющие символы запрещены проверкой книги.
- Ничего нового в логи, URL и аналитику не попадает; ID копируется только через copyText.

## Что не гарантируем
- Контакт не подтверждает личность: имя это ваша метка. Два разных ID можно назвать одинаково (хвост ID виден), сверки отпечатков ключей нет.
- Сервер видит, когда вы меняете книгу, и примерно её размер; видит и запрос ключей по ID при добавлении (как при создании чата).
- Удаление из контактов не стирает копии книги у хостинга сразу.
- Без связи и со «спящим» сервером список недоступен (нет кэша на устройстве).

- №34a «Описание в формате книги + слияние» (сложная, автослияние нет): packages/crypto (поле notes, decryptContactBookFull, лимит размера), контроллер сохраняет описания, слияние по одному действию. UI нет.
- №34b «Действия контактов в контроллере» (сложная, автослияние нет): addContact, saveContactNote, removeContact, коды ошибок (invalid_id, own_id, already_contact, limit_reached, book_too_large, contacts_not_loaded, user_not_found, server_unavailable, bad_peer_key, save_failed).
- №34c «Экран контактов и карточка» (интерфейс, автослияние нет: трогает клиентское состояние): пункт меню, список, добавление, карточка, подтверждение удаления, RU/EN/UK, видимое место каждой ошибки, сброс состояния в трёх путях, e2e, ширина 360 px через getComputedStyle.
- №34d «Шапка чата открывает карточку».
- Ручная проверка владельца после №34c: обычное окно, инкогнито, 360 px, Offline, два устройства (убрать контакт на одном, переименовать на другом).
