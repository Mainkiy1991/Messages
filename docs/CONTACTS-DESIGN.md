## Что есть сейчас (в main после PR #97)
- Книга контактов: зашифрованный на устройстве словарь «ID → имя» плюс необязательные описания (до 200 символов). Сервер хранит один шифрблок и номер версии, миграции и сервер не менялись. Лимиты: имя 1–64 символа, 1000 контактов, открытый текст книги до 200 КиБ.
- Контроллер (ChatController): addContact, renameContact, saveContactNote, removeContact (результат {ok} или код ContactError), saveContactName (прежнее поведение), признаки состояния contacts, contactNotes, contactsReady (книга успешно загружена), contactsError. При конфликте версий действие заново применяется к свежей книге (удалённый на другом устройстве контакт не возвращается).
- Экран «Контакты»: накладка поверх приложения (apps/web/src/components/contacts-screen.tsx), пункт «Контакты» в меню профиля. Виды: list (список: сортировка без учёта регистра, имя, хвост ID 10 символов, описание одной строкой), add (добавление по ID: ID, имя обязательно, описание необязательно), card (карточка контакта: имя, полный ID, моё описание, «Написать», «Убрать из контактов» с подтверждением на месте), peer (карточка собеседника, который не в контактах: полный ID, кнопка «Добавить в контакты»), peerAdd (форма добавления собеседника: ID только для чтения, имя обязательно, описание необязательно). Каждая ошибка показывается в своём месте (add, name, note, write, remove, copy).
- Открытие из чата: тап по имени в шапке чата (кроме «Избранного») открывает карточку собеседника (вид card, если контакт; peer, если нет) в том же окне и с той же записью истории (признак fromChat; «Написать» из такой карточки не нужно). Пункт меню чата (⋯): «Карточка контакта» (если контакт) или «Добавить в контакты» (если нет). Встроенное редактирование имени в шапке чата удалено: имя меняется только в карточке.
- Режим выбора («Новый чат» → «Из контактов»): заголовок «Выбрать контакт», без «Добавить контакт», тап по строке открывает чат. Новый чат по ID с введённым именем сохраняет контакт (подпись поля имени об этом сообщает).
- Поля ввода (имя, описание, ID) это SingleLineField (textarea в одну строку): панель автозаполнения Google не появляется, автофокус при открытии не ставится (решение владельца 12: фокус только как ответ на нажатие, например поле правки после нажатия карандаша). Enter сохраняет имя и описание (№36b1).
- Шаги «Назад» (стрелка и Escape) внутри окна: редактор открыт → отмена редактирования; подтверждение удаления открыто → отмена подтверждения; карточка, peer, peerAdd или add → список (peerAdd → peer; из окна, открытого из чата, закрывает окно); список → закрыть окно. Escape слушается на document (окно, открытое тапом, не забирает фокус). Во время busy (идёт сохранение или удаление) back() не срабатывает.

## Модель имён (подтверждена владельцем 25 ноября)
Имя собеседника хранится ТОЛЬКО в книге контактов; «дать имя» = «сохранить в контакты» (так работает код с самого начала: contactLabel берёт имя из книги, иначе хвост ID). Добавление в контакты должно быть явным действием через карточку. Убрать контакт: чат и сообщения остаются, имя в чате пропадает, остаётся хвост ID (в Telegram после удаления контакта показывается имя, которое человек выбрал сам; у нас это появится после этапа «Профиль»; сейчас ID).
Удалить чат или очистить чат контакт не трогает.

## История браузера (кнопка «Назад» телефона)
Окно «Контакты» занимает ОДНУ запись истории: «Назад» телефона закрывает окно целиком (не шаг за шагом) и оставляет пользователя в приложении на прежнем месте. Схема в main.tsx (№34d): contactsOpenRef и contactsHistoryRef; openContacts() делает pushState({...state, contacts: true}); closeContacts() вызывает history.back(), если запись принадлежит окну; обработчик popstate первым делом закрывает окно и выходит; когда из окна открывается чат (activePeer меняется при открытом окне), запись окна ЗАМЕНЯЕТСЯ на {chat: activePeer} (replaceState), поэтому «Назад» из такого чата ведёт на список чатов; сброс обоих ref в трёх местах (enter, confirmLogout, onDeviceRevoked). Устаревший флаг contacts в history.state безвреден: он учитывается только при contactsOpenRef.current. Замену записи делать только если activePeer не пустой. Шаги «Назад» телефона по схеме forward (как в окне «Новый чат») для окна контактов будут сделаны в этапе «Профиль» (общий механизм).

## Как защищаем
- Имена, описания и ID контактов шифруются на устройстве (ключ истории), сервер видит только шифрблок, версию и его размер. Описание собеседнику не уходит.
- Добавляя контакт, клиент проверяет подпись публичных ключей собеседника, как при создании чата.
- Тексты выводятся как обычный текст; управляющие символы запрещены (в описаниях проверкой книги, в именах проверкой контроллера для новых методов; старые имена с такими символами читаются).
- Ничего нового в логи, URL и аналитику не попадает.

## Что не гарантируем
- Контакт не подтверждает личность: имя это ваша метка. Два разных ID можно назвать одинаково (хвост ID виден), сверки отпечатков ключей нет.
- Сервер видит, когда вы меняете книгу, и примерно её размер; видит и запрос ключей по ID при добавлении.
- Удаление из контактов не стирает копии книги у хостинга сразу.
- Без связи и со «спящим» сервером список недоступен (нет кэша на устройстве).
- Окно без ловушки фокуса, на широких экранах фон под ним кликабелен (бэклог).
