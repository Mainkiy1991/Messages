# ПРОЕКТ «КОНТАКТЫ» (черновик от 24 ноября 2026, ждёт утверждения владельцем)

Файл ветки `notes`, в `main` не попадает. Статус и порядок работ: docs/PROJECT-CONTEXT.md.

## Что делаем
Пункт «Контакты» в меню профиля открывает список ВСЕХ сохранённых контактов, независимо от того, есть ли с ними чат. В списке: имя и последние 10 символов ID. Действия: открыть чат, добавить по ID, переименовать, убрать из контактов, скопировать ID. Сервер, миграции и packages/crypto не меняются: всё строится на существующей зашифрованной книге контактов.

## Что есть в основе (проверено по коду 24 ноября, main после PR #82)
- Книга контактов: словарь «ID → имя». Имя обязательно: пустого имени книга не принимает (1–64 символа без управляющих), максимум 1000 записей. Контакт — это запись с именем; чат без имени контактом не считается.
- Книга шифруется на устройстве ключом истории, сервер хранит один шифрблок и номер версии (защита от перезаписи: при расхождении версий сервер отвечает 409).
- ChatController: saveContactName (пустое имя = удалить запись), loadContacts, state.contacts, contactsError; openChat (проверяет ключ собеседника через getVerifiedPeerKey и открывает чат); contactLabel (имя или хвост ID).
- Сегодня контакт можно задать только в шапке чата или в форме «Новый чат»; списка контактов нет.
- «Удалить чат» книгу не трогает: имя остаётся.
- Найденный старый недочёт (не регрессия, в бэклоге как «слияние контактов при конфликте»): при расхождении версий saveContactName склеивает книгу так, что запись, удалённая на другом устройстве, может вернуться. Для «убрать из контактов» это недопустимо, чинится в первой части.

## Решения
1. Контакт и чат независимы. Чат можно удалить или очистить, контакт остаётся; контакт можно убрать, чат остаётся.
2. Убрать из контактов = удалить запись из книги. Чат и сообщения не трогаются, в списке чатов собеседник показывается по хвосту ID. Перед удалением окно подтверждения с этим пояснением; кнопка не активна, пока идёт запрос.
3. Добавить по ID: поля «ID» и «Имя» (имя обязательно, иначе книга запись не примет). Порядок: проверка формата ID → отказ для собственного ID («Избранное» в контакты не входит) → отказ, если контакт уже есть → проверка ключа собеседника как при создании чата (getVerifiedPeerKey) → сохранение в книгу. Чат при добавлении не открывается и не создаётся.
4. Переименовать: на экране «Контакты» пустое имя не удаляет контакт, а даёт ошибку «Введите имя» (удаление только отдельной кнопкой). Поведение шапки чата не меняется.
5. Одинаковые имена у разных ID разрешены. Чтобы не перепутать, в списке всегда рядом показывается хвост ID.
6. Лимит 1000: при добавлении 1001-го контакта своя понятная ошибка в форме (сейчас общая «Не удалось сохранить имя»).
7. Слияние при расхождении версий (бэклог): вместо склейки двух книг агент заново применяет ОДНО действие пользователя (добавить, переименовать или убрать один ID) к свежей книге с сервера и сохраняет её. Так удалённая на другом устройстве запись не возвращается.
8. Офлайн и загрузка: книга живёт только в памяти (на диск не кэшируем, как историю). Пока книга не загружена или не расшифрована (contactsError), экран показывает ошибку и не позволяет добавлять, переименовывать и убирать. Все изменения требуют связи, при ошибке сообщение видно прямо в форме или строке.
9. Вид: внутри экрана home вместо списка чатов открывается список контактов с кнопкой «Назад» (без новых маршрутов, window.history.state не трогаем). Строка: клик по ней открывает чат; справа кнопка «⋯» с меню «Скопировать ID», «Переименовать», «Убрать из контактов» (стили и поведение как у меню чата, подтверждение копирования на самой кнопке через copyText). Сортировка по имени без учёта регистра. Поиска нет (в бэклог).
10. Сброс состояния: признак «открыт экран контактов» и все его черновики сбрасываются во всех трёх путях (выход confirmLogout, вылет onDeviceRevoked, новый вход enter()), урок №28f; при F5 экран контактов не восстанавливается.

## Как защищаем
- Имена и ID контактов шифруются на устройстве (ключ истории, отдельная метка HKDF), сервер видит только шифрблок и версию. Новых данных на сервере нет.
- Добавляя контакт, клиент проверяет подпись публичных ключей собеседника (verifyUserKeys), как при создании чата.
- Имена выводятся как обычный текст; управляющие символы запрещены проверкой книги.
- Ничего нового в логи, URL и аналитику не попадает; ID копируется только через copyText.

## Что не гарантируем
- Контакт не подтверждает личность: имя это ваша локальная метка. Два разных ID можно назвать одинаково; мы показываем хвост ID, но сверки отпечатков ключей нет.
- Сервер видит, когда вы меняете книгу контактов, и примерно её размер; видит и запрос ключей по ID при добавлении (как при создании чата).
- Удаление из контактов не стирает копии книги у хостинга сразу.
- Нет кэша на устройстве: без связи и с «спящим» сервером список недоступен.
