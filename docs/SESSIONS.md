# Устройства и серверные сессии

Устройство имеет случайный Ed25519-ключ. Публичный ключ идентифицирует устройство как 64-символьную hex-строку, приватный ключ хранится только у устройства. Метка устройства шифруется клиентом и отправляется серверу как ciphertext; сервер хранит и отдаёт только зашифрованную строку.

## Регистрация

Клиент получает одноразовый challenge через `POST /auth/challenge`, затем подписывает challenge ключом личности вместе с публичным ключом устройства. Регистрация подтверждает и привязку ключа шифрования к ключу личности.

`POST /auth/device/register` принимает `challengeId`, `identityPublicKey`, `encryptionPublicKey`, `keyBindingSignature`, `devicePublicKey`, `deviceLabel`, `signature`. Успех: `200 { token, expiresAt, userId, deviceId }`. Неверные подписи и данные: `401 { error: "invalid_credentials" }`; повторно отозванное устройство: `403 { error: "device_revoked" }`.

## Вход

`POST /auth/device/login` принимает `challengeId`, `deviceId`, `signature`. Подпись создаётся только приватным ключом устройства. Успех: `200 { token, expiresAt, userId, deviceId }`. Неизвестное устройство или неверная подпись: `401 { error: "invalid_credentials" }`. Отозванное устройство с верной подписью: `403 { error: "device_revoked" }`.

Challenge одноразовый и живёт ограниченное время. Формат challenge и ключей проверяется сервером.

## Работа с устройствами

- `GET /devices` требует bearer-токен и возвращает активные устройства пользователя с меткой, датами создания и последнего входа и признаком `current`.
- `DELETE /devices/:deviceId` отзывает другое устройство пользователя. Текущего устройства нельзя отозвать этим запросом: `409 { error: "current_device" }`. Повтор отозванного устройства возвращает `204`.
- `POST /devices/revoke-others` с пустым `{}` отзывает все остальные устройства пользователя, завершает их сессии и удаляет остальные старые сессии без привязки к устройству.
- Выход (`POST /auth/logout`) отзывает устройство сессии и завершает все его сессии.

Отзыв немедленно удаляет сессии отозванного устройства и закрывает связанные WebSocket-соединения. Сторонний пользователь или неверный формат не раскрывают чужие устройства.

При завершении сессии сервер отправляет WebSocket-кадр `{"type":"session_ended"}` перед закрытием сокета. Клиент начинает повторный вход по устройству и показывает экран входа при отзыве устройства; если `auth_ok` не пришёл за 8 секунд, соединение закрывается и переподключается с ограничением повторного входа.

Старый `POST /auth/login` продолжает работать для обратной совместимости. Его сессии не привязаны к устройству.

## Чего не гарантируем

- Не защищаем от человека, которому известна сид-фраза аккаунта.
- Не защищаем от копирования ключа личности из браузерной версии до перехода на ключи устройства.
- Офлайн-устройство узнает об отзыве только при следующем обращении к серверу.
- Скопированный заранее токен или приватный ключ устройства остаётся действующим до момента отзыва и обращения за проверкой сессии.
- Сервер видит метаданные сессий: число и идентификаторы устройств, а также время входов и использования. Метку сервер видит только как зашифрованный текст.
- Старый вход будет отключен отдельным этапом №28e.
