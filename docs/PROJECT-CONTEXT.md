## ТЕКУЩАЯ РАБОТА: №28f (PR #76), вердикт: ПРИНЯТЬ
Дефект (найден владельцем при ручной проверке №28e): после «вылета» вкладки (устройство завершили из другого места) новый аккаунт, созданный без F5, открывал пустой чат прежнего аккаунта. Причина: открытый чат хранится в window.history.state = { chat: peerId }; выход confirmLogout очищал его, а путь onDeviceRevoked и функция enter() нет (пропуск со времён №28c1). Данных не утекло.
Исправление (проверено построчно): функция clearChatHistoryEntry() (replaceState(null…) и chatHistoryRef.current=false) вызывается в confirmLogout, в onDeviceRevoked (finally, до setKeys(null)) и в enter() (до setScreen("home")); при восстановлении сессии после F5 и разблокировке PIN очистки нет. Изменены только main.tsx и devices.spec.ts.
Доработка №28f1 (по замечанию техрука: первый вариант e2e мог пройти без исправления, так как openChat ждёт ответ сервера перед открытием чата, а проверки «чата нет» срабатывали раньше): теперь тест проверяет само состояние: (1) после device-revoked-notice window.history.state равен null (ловит пропуск в onDeviceRevoked; до исправления там остаётся { chat: A }, потому что тест открывает «Избранное» и срабатывает pushState); (2) на экране приветствия в историю записывается заглушка { chat: "a"*64 }, после создания нового аккаунта (profile виден) history.state снова null (ловит пропуск в enter()); оставлена проверка .messenger.show-chat count 0; слабые проверки удалены; sleep нет; перед тестом комментарий про порядок после паузы лимита /auth/challenge (3 входа). Мутации e2e локально не гонялись (e2e требует PostgreSQL и браузер), корректность проверена разбором порядка вызовов: оба новых expect детерминированы (очистка выполняется синхронно до показа уведомления и экрана home).
