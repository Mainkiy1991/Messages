## ИДЕЯ
Мессенджер без привязки к почте и телефону. Пользователь создаёт или вводит сид-фразу (12 или 24 слова, BIP-39) и входит с любого устройства: подтягивается история, можно общаться. Всё шифруется и расшифровывается на устройстве, сервер не читает сообщения. Проект открытый, некоммерческий. MVP выполнен (текстовые чаты 1-на-1 в браузере, интерфейс RU/EN/UK), идёт доработка функций и подготовка к аудиту.

Общий PIN на всех устройствах (идея владельца 19 ноября): PIN, однажды установленный, автоматически ставится на любом устройстве после входа по сид-фразе; выключить можно сид-фразой или верным PIN, забытый PIN сбрасывается только сид-фразой. Разбор техрука: это замок на каждом устройстве (защита копии ключей в браузере), а не второй фактор против того, у кого есть сид-фраза (раз сброс по сид-фразе). Как: PIN хранится на сервере только зашифрованным ключом истории (блок настроек по образцу книги контактов, версия и защита от перезаписи); новое устройство после входа читает его и защищает свои ключи тем же PIN. Хорошо дополняет №28: скопированные из браузера ключи без PIN бесполезны. Решения владельца см. выше (выключение, узнавание при разблокировке, конфликт версий). Осталось решить в коротком проекте: формат блока настроек и миграция 011, что при офлайне (смена и выключение только при связи, ошибка видна; офлайн-устройство держит старый PIN до синхронизации), как устройство, которое знает только старый PIN, получает новый (разблокирует старым, затем перешифровывает локальную копию новым). Хранение ключей и блок PIN уже переписаны в №28c1 (PIN-блок v2), так что ограничение «не делать до №28c» снято; делать после №28e.

## БЭКЛОГ МЕЛКИХ ДОРАБОТОК (клиент и протокол; безопасность и аудит в закрытой части)
- CSS кнопок сообщения (.message-edit, .message-delete) показывает их по :focus-within строки: это нарушает правило процесса (после клика мышью по кнопке она остаётся видимой). Заменить на :focus-visible и добавить e2e с Tab.
- Корзинка на ПК: состояние hoverRevealPeerId сбрасывается при смене состава или порядка списка (например, когда приходит новое сообщение и чат поднимается наверх): корзинка под мышью пропадает до нового наведения. Сбрасывать только если строка исчезла.
- e2e клавиатуры корзинки (сценарий удаления из списка) идёт после наведения мыши и через item.focus(), поэтому по отдельности клавиатурный показ не доказывает (логика CSS верна). Добавить сценарий: мышь вне строки, Tab до корзинки, opacity 1.
- Меню чата остаётся открытым при смене чата через форму нового чата (так было и раньше): закрывать при смене activePeer.
- long-press.ts: флаг подавления клика сбрасывается только касанием; на гибридных устройствах (сенсор и мышь) один клик мышью после долгого нажатия без click может проглотиться. Исправление в одну строку: сбрасывать флаг в onPointerDown для любого типа указателя.
- Блок ошибки копирования ID появляется в DOM уже с role=alert (скринридеры могут не озвучить); при желании постоянная область.
- e2e на «Очистить чат» в «Избранном» (удаление покрыто в №27d2b).
- Рамка messages_erased меняет только загруженные в память сообщения, остальное догружается стёртыми строками при открытии чата.
- Известный максимум seq скрывает пропущенное при живых кадрах (для чужих кадров остаётся только при пропуске кадра на живом соединении).
