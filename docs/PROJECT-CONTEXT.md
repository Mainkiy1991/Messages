## ИДЕЯ
Мессенджер без привязки к почте и телефону. Пользователь создаёт или вводит сид-фразу (12 или 24 слова, BIP-39) и входит с любого устройства: подтягивается история, можно общаться. Всё шифруется и расшифровывается на устройстве, сервер не читает сообщения. Проект открытый, некоммерческий.

ЭТАП MVP (выполнен, идёт подготовка к аудиту): текстовые чаты 1-на-1 в браузере, интерфейс RU/EN/UK.

## ТЕХНИЧЕСКИЕ РЕШЕНИЯ
- Стек: TypeScript, React + Vite, Node.js + WebSocket, PostgreSQL (Neon), хостинг Render. Монорепо pnpm: apps/web, apps/server, packages/crypto.
- Ключи: сид BIP-39 → HKDF → отдельные ключи: личность (Ed25519, публичный = адрес), шифрование сообщений (X25519), шифрование истории (симметричный).
- Сообщения: libsodium (X25519 + XChaCha20-Poly1305). Копия для отправителя (senderCopy) шифруется ключом истории.
- Вход на сервер без пароля: challenge-response (подпись случайной строки ключом личности).
- Сессия на клиенте: IndexedDB. Необязательный PIN: Argon2id (64 MiB, 3 итерации, соль 16 байт) + XChaCha20-Poly1305, blob v1; PIN от 6 символов, NFKC; паузы после неверного PIN: 5-я ошибка 5 мин, 6-я 15 мин, 7-я и далее 60 мин; сбой KDF не считается ошибкой PIN; серверный токен при PIN шифруется отдельным ключом HKDF (метка messages/v1/pin-server-session).
- Формат сообщения v2: внутри шифртекста {v:2, id (16 случайных байт), type:"text", text, sentAt, rev?}; в AAD отправитель, получатель, их ключи и id; копия отправителя привязана к автору, собеседнику, id и clientMsgId. Правка = замена содержимого той же строки (rev 1..100, id и sentAt те же). Дедупликация по (автор, id), остаётся меньший seq. Неизвестный type молча пропускается; так же пропускаются старые строки type edit, delete_request, delete_answer (код этих механизмов из packages/crypto удалён в №27c2, старые строки читаются как неизвестный тип; тесты есть для живых кадров, истории и очереди). v1 читается без защиты от повтора. После изменения формата или протокола просим всех обновить страницу (F5).
- Правка и удаление своих сообщений (на месте, без очереди, нужна связь): PUT /messages/:id {ciphertext, senderCopy} → 204 (404 чужая или нет, 409 уже стёртая); DELETE /messages/:id без тела и без Content-Type → 204 (повтор тоже 204): сервер стирает шифртекст и копию, строка остаётся с признаком deleted. У собеседника и на других устройствах автора на месте сообщения заглушка («Вы удалили сообщение» / «Собеседник удалил сообщение»; в списке чатов «Сообщение удалено»). Подряд идущие заглушки одного автора показываются одной строкой во множественном числе (только отображение). Чужое сообщение удалить нельзя, срока давности нет. В «Избранном» тоже можно, тексты без слова «собеседник» (подтверждение «Удалить эту заметку?»).
- Очистка и удаление чата (№27c2, сделано): «Очистить чат» = DELETE /conversations/:peerId (только у себя, на всех своих устройствах, ответ {clearedBeforeSeq}); «Удалить чат» = POST /conversations/:peerId/erase с телом {} (стирает все мои строки этого чата и очищает у себя, ответ {erased, clearedBeforeSeq}). Собеседнику приходит рамка messages_erased {from,to,upToSeq,changeSeq}: его входящие строки от автора с seq не выше upToSeq становятся заглушками; своим устройствам приходит conversation_cleared. При ошибке или без связи чат не меняется, ошибка видна в окне подтверждения. Проект: docs/DELETE-OWN.md (читать первым при работе над ними).
- Изменения доходят рамками WebSocket message_updated, message_deleted, messages_erased. У каждой строки change_seq (общий счётчик); GET /conversations отдаёт lastChangeSeq, GET /history/:peerId?changedAfter=n догружает изменённые строки (клиент берёт запас 100). Стёртая строка отдаётся с deleted:true и пустым шифртекстом.
- Синхронизация отправленных между устройствами (№27e, PR #57, принят): при новой отправке сервер шлёт остальным сокетам автора (кроме приславшего) живую рамку own_message {id, to, clientMsgId, senderCopy, createdAt, seq}; без ящика и ack; для сообщений самому себе и повторов не шлётся. Клиент расшифровывает senderCopy ключом истории и добавляет исходящее сообщение со статусом «отправлено», без дубликатов с историей. До этого другие устройства автора видели отправленное только после F5 (в «Избранном» работало, там получатель сам автор).
- Сервер хранит: публичные ключи, шифртекст, метаданные (кто/кому/когда, статусы, seq, change_seq, факт правки или стирания, отметки очистки conversation_clears).
- API: история GET /history/:peerId (страницами), список чатов GET /conversations, зашифрованные контакты GET/PUT /contacts (версия + защита от перезаписи). Статусы: отправляется / отправлено / доставлено / прочитано; онлайн-статусы; heartbeat (ping 25 с, таймаут 10 с, только видимая вкладка).
- Интерфейс чата: кнопка «назад» = стрелка (подпись «Назад» сохранена для скринридеров); меню «⋯» с двумя пунктами друг под другом; ширина пузыря на 360 px около 60% (улучшено в №27c3, см. бэклог).
- Ошибки отправки, правки и удаления показываются над полем ввода или в окне подтверждения; ошибка имени контакта под шапкой чата.
- Язык: авто + выбор, ключ localStorage messages-lang.
- Документация: README, docs/CRYPTO.md (аудит в разделе 10), docs/DEPLOY.md, docs/USER-GUIDE.ru/en/uk.md, docs/DELETE-OWN.md (в нём же проект этапа №27d), docs/DELETE-REQUEST.md (история решения, не реализуется), AGENTS.md, .github/copilot-instructions.md и .clinerules/.

## ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ (приняты осознанно)
- Потеря сид-фразы = потеря аккаунта, восстановления нет.
- Сервер видит метаданные (кто кому пишет и когда, факт правки, очистки или стирания), но не содержимое.
- Нет forward secrecy (утечка сид-фразы открывает и старую переписку).
- Код сайта приходит с сервера; смягчается открытым исходным кодом.
- Бесплатный Render засыпает через 15 минут, пробуждение около минуты.
- Паузы PIN обходятся при доступе к F12 и копии данных (защищает длина PIN); разблокированную сессию PIN не защищает.
- Правка и удаление не отзывают уже прочитанное, скопированное или сфотографированное; у изменённого клиента собеседника не действуют; без связи не работают (очереди нет); клиент без обновления (F5) покажет «не удалось расшифровать» или старое состояние.
- Резервные копии базы у хостинга могут жить ограниченное время.

## РЕШЕНИЯ ВЛАДЕЛЬЦА (принципы)
- Проект личный и некоммерческий, платит владелец из своего кармана. Платную инфраструктуру (серверы-ретрансляторы и т.п.) пока не берём; вместо неё честные предупреждения пользователю в интерфейсе и документации. Позже, при появлении денег, убираем компромисс.
- Разрабатываем максимально близко к концепции: без привязки к почте и телефону, всё зашифровано. Экономим токены агента: ТЗ маленькие.
- Полный аудит безопасности откладывается до момента, когда все желаемые функции будут сделаны и мы решим публиковать проект. До аудита адрес сайта не публикуем и чужих людей не зовём. Каждое «сложное» ТЗ при этом проверяется построчно.
- Очистка чата оставляет контакт в списке (чтобы не потерять ID собеседника); удаление чата убирает его из списка (решение 16 ноября 2026).

## БЭКЛОГ МЕЛКИХ ДОРАБОТОК (клиент и протокол; безопасность и аудит в закрытой части)
- Кнопки правки и удаления накладкой, чтобы пузырь занимал почти всю ширину (на 360 px сейчас около 60%, две скрытые кнопки по 36 px занимают место внутри строки).
- e2e на «Очистить чат» и «Удалить чат» именно в «Избранном» (пока только тексты и юнит-тесты, проверено вручную).
- Рамка messages_erased меняет только загруженные в память сообщения, остальное догружается стёртыми строками при открытии чата (проверено вручную).
- Известный максимум seq скрывает пропущенное при живых кадрах (источник для своих сообщений закрыт в №27e; для чужих кадров остаётся только при пропуске кадра на живом соединении).
- Украинская заглушка во множественном числе звучит «Ви видалили кілька повідомлень» (смысл тот же, правок не требуется).
- Время неотправленного сообщения после перезагрузки.
- Слияние контактов при конфликте; удаление имени контакта вместе с чатом (решение: при «Удалить чат» имя остаётся в зашифрованной книге контактов).
- Не грузить историю всех чатов при загрузке страницы, только при открытии чата.
- Очистка чата с другого устройства убирает неподтверждённое сообщение этого чата; клиент скрывает чаты сверх 500.
- Возможность отключить отметки о прочтении; «скрыть, когда я был в сети» (вместе со страницами аккаунтов).
- Вернуть в e2e перезапуска сервера проверку «в сети» (убрана в PR #17).
- Вынести общий код расшифровки (сейчас четыре места: fetchHistory, handleFrame (message), decryptUpdatedRow, own_message в handleFrame; аккуратно, крипто).
- libsodium даёт около 186 КБ gzip (грузится лениво, только для PIN): вспомнить при оптимизации.
- composerError не очищается при вводе текста (уходит при успехе, отмене правки или смене чата).
- Ошибка сохранения имени контакта (contact-name-error) без автотеста.
- mergeMessages: стёртая строка сбрасывает countedUnread без уменьшения unreadCount чата (на практике недостижимо).
- Пересылка = новое сообщение, пометка «переслано» это слова пересылающего.
- v2 неизвестной версии молча пропускается: учесть в новых задачах.
- Расхождение правок с двух устройств при одинаковом rev: у одного остаётся своя версия до F5.
- Сервер может отдать старую версию строки (откат ловится по rev только пока страница открыта).
- Избранное: сообщение, пришедшее на другое устройство обычным кадром, не имеет clientMsgId: не правится и не обновляется до перезагрузки истории.
- Сенсорный режим правки и удаления проверить на телефоне.
- Подсветка выбранного сообщения при подтверждении удаления.
- После «Удалить чат» собеседник всё ещё видит статус «в сети».
