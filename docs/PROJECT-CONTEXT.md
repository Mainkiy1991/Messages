## ТЕКУЩАЯ РАБОТА: проект №31 «Общий PIN» (docs/PIN-SYNC-DESIGN.md, УТВЕРЖДЁН 23 ноября)
Решения владельца: 1) новое устройство получает PIN автоматически; подсказка «не используйте PIN от банка»; 2) один общий PIN без исключений.
Этап №31c из проекта разделён на два ТЗ (большой дифф): №31c (синхронизация и действия) и №31d (конфликт и сброс по сид-фразе).
- №31c ВЫДАНО (ветка feat/31c-pin-sync-ui, сложная, автослияние нет): API-функции getPinSettings/putPinSettings; ChatController.withSession; модуль lib/pin-sync-runner.ts (сверка при запуске/разблокировке/входе, публикация локального PIN, применение enable/change/disable, действия пользователя «включить, сменить, выключить» через сервер); подключение в main.tsx; видимые сообщения и ошибки; тексты RU/EN/UK; ограничение PIN 64 символа; e2e на двух контекстах.
- №31d (после слияния №31c): конфликт 409 с вводом актуального PIN и «Сбросить по сид-фразе» (выключить PIN или задать новый), e2e.
Решения техрука в №31c (внести в PIN-SYNC-DESIGN.md при приёмке №31d): (1) PIN устройства передаётся сверке через ref, который читается и обнуляется один раз при создании контроллера, нигде не хранится; если на устройстве PIN включён, а PIN в памяти нет, сверка пропускается (иначе устройство ошибочно сочтёт PIN выключенным); (2) enable_pin из сверки не применяется при непустой очереди исходящих (enablePin стирает очередь): показывается сообщение, сверка повторится позже; (3) смена и выключение: сначала проверка текущего PIN локально, потом чтение блока и запись на сервер, потом локально; версия отмечается только после локального применения; (4) в №31c при расхождении версии (другое устройство уже сменило) действие отменяется со словами «перезагрузите страницу: PIN обновится сам» (полноценный ввод актуального PIN в №31d); (5) PIN длиннее 64 символов (после NFKC) не принимается; уже заданный старый PIN длиннее 64 не публикуется, пользователю видна подсказка сменить PIN; (6) версия сверки хранится отдельным ключом pinSyncVersion, блок 553 байта.
