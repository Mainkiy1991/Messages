## ИДЕЯ
Мессенджер без привязки к почте и телефону. Пользователь создаёт или вводит сид-фразу (12 или 24 слова, BIP-39) и входит с любого устройства: подтягивается история, можно общаться. Всё шифруется и расшифровывается на устройстве, сервер не читает сообщения. Проект открытый, некоммерческий. MVP выполнен (текстовые чаты 1-на-1 в браузере, интерфейс RU/EN/UK), идёт доработка функций и подготовка к аудиту.

## РЕШЕНИЯ ВЛАДЕЛЬЦА (принципы)
- Проект личный и некоммерческий, платит владелец. Платную инфраструктуру (серверы-ретрансляторы и т.п.) пока не берём; вместо неё честные предупреждения пользователю. Позже, при появлении денег, убираем компромисс.
- Максимально близко к концепции: без привязки к почте и телефону, всё зашифровано. Экономим токены агента: ТЗ маленькие.
- Полный аудит безопасности откладывается до момента, когда все желаемые функции сделаны и решено публиковать проект. До аудита адрес сайта не публикуем и чужих людей не зовём. Каждое «сложное» ТЗ проверяется построчно.
- Очистка чата оставляет контакт в списке (чтобы не потерять ID собеседника); удаление чата убирает его из списка. Старые очищенные и удалённые чаты (до миграции 009) остаются скрытыми.
- Интерфейс: подтверждение копирования показывается на самой кнопке; корзинка в списке на компьютере появляется через ~1 с после наведения и не остаётся на выбранном чате.
- Сроки не срочных пожеланий («Контакты» и др.) техрук определяет сам.
- Файл контекста существует, чтобы вести проект к цели, а не чтобы укладываться в лимит (решение владельца 18 ноября).
- №28: владелец потребовал, чтобы «Завершить сессии» работало и против изменённого клиента, и утвердил усиленный вариант (ключи устройств; отозванный браузер при следующем контакте стирает локальные данные и просит сид-фразу). 19 ноября.
- Общий PIN (19 ноября): PIN может выключить не только сид-фраза, но и сам верный PIN (владелец; техрук согласен: разблокированная вкладка без знания PIN выключить его не сможет); другие устройства узнают о смене или выключении при следующей разблокировке; при одновременной смене с двух устройств побеждает первая, второму нужно ввести уже изменённый PIN (оптимистичная блокировка по версии: сервер отвечает 409, устройство читает новый блок, просит ввести актуальный PIN как доказательство, что человек его знает, и повторяет).

## ПРАВИЛА ПРОЦЕССА (дополнения)
- Из ветки notes PR не создавать и кнопку «Compare & pull request» для неё не нажимать (GitHub показывает её сам после каждой записи в notes): CI проверяет prettier во всех файлах (так появились красные PR #58 и #60). Если PR из notes открылся, просто закрыть.
- Серверное ТЗ не обещает изменений клиента: если клиент не меняется, ожидания UI в e2e не переписывать «под новое поведение».
- Владелец присылает вместе с номером PR и отчёт агента. Код из отчёта сверяю с реальным диффом. Репозиторий публичный: через bash можно клонировать ветку PR и локально прогнать web и crypto тесты (corepack pnpm install --frozen-lockfile, corepack pnpm --filter @messages/crypto test; pnpm напрямую в песочнице не установлен, нужен corepack); серверные тесты и e2e нужна база, их проверяет CI. Для ветки: git fetch --depth 50 origin main:refs/remotes/origin/main <ветка>:refs/remotes/origin/<ветка>.
- Размер файлов контекста: PROJECT-CONTEXT.md ориентир до ~20 КБ (читается и переписывается целиком при каждом вердикте), TECH-DECISIONS.md без жёсткого лимита (до ~40 КБ, правится редко). Сворачивать только то, что реально устарело (сделанные пункты порядка, закрытые мелочи бэклога); полезное не выбрасывать.
- В CSS не использовать :focus-within для показа скрытых кнопок (клик мышью даёт фокус); использовать :focus-visible. В e2e для клавиатурного фокуса идти клавишей Tab при мыши вне строки (не .focus() и не при наведении).
- Номера: доработки к принятому ТЗ получают суффикс (№29a); №28 это «Активные устройства» (этапы №28a–№28e).
- Геометрические критерии в ТЗ (доля ширины, позиции) сверять с данными конкретного теста: у короткого сообщения пузырь по ширине текста, требовать от него долю ширины нельзя (урок №30). В каждом ТЗ с CSS агенту писать: «если требование ТЗ нельзя выполнить без правил вне ТЗ, не подгоняй CSS, остановись и сообщи в отчёте». В диффе CSS проверять, что нет правил вне ТЗ (особенно width/flex).

- Если владелец пишет, что PR создать нельзя («nothing to compare»): агент запушил ветку до коммита. Лечится коммитом и пушем в ту же ветку. ## БЭКЛОГ МЕЛКИХ ДОРАБОТОК (клиент и протокол; безопасность и аудит в закрытой части)
- CSS кнопок сообщения (.message-edit, .message-delete) показывает их по :focus-within строки: это нарушает правило процесса (после клика мышью по кнопке она остаётся видимой). Заменить на :focus-visible и добавить e2e с Tab.
- Корзинка на ПК: состояние hoverRevealPeerId сбрасывается при смене состава или порядка списка (например, когда приходит новое сообщение и чат поднимается наверх): корзинка под мышью пропадает до нового наведения. Сбрасывать только если строка исчезла.
- e2e клавиатуры корзинки (сценарий удаления из списка) идёт после наведения мыши и через item.focus(), поэтому по отдельности клавиатурный показ не доказывает (логика CSS верна). Добавить сценарий: мышь вне строки, Tab до корзинки, opacity 1.
- Меню чата остаётся открытым при смене чата через форму нового чата (так было и раньше): закрывать при смене activePeer.
- long-press.ts: флаг подавления клика сбрасывается только касанием; на гибридных устройствах (сенсор и мышь) один клик мышью после долгого нажатия без click может проглотиться. Исправление в одну строку: сбрасывать флаг в onPointerDown для любого типа указателя.
- Блок ошибки копирования ID появляется в DOM уже с role=alert (скринридеры могут не озвучить); при желании постоянная область.
- e2e на «Очистить чат» в «Избранном» (удаление покрыто в №27d2b).
- Рамка messages_erased меняет только загруженные в память сообщения, остальное догружается стёртыми строками при открытии чата.
- Известный максимум seq скрывает пропущенное при живых кадрах (для чужих кадров остаётся только при пропуске кадра на живом соединении).
