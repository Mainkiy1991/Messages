## ТЕКУЩАЯ РАБОТА: проект №31 «Общий PIN» (docs/PIN-SYNC-DESIGN.md)
Решение владельца 24 ноября: пункт «мгновенное оповещение другим устройствам кадром WebSocket» (раньше в «Чего НЕ делаем») ВКЛЮЧЁН в проект. Порядок: №31e (живое обновление) → №31d (конфликт и сброс по сид-фразе).
Проект №31e (кратко): сервер после успешной записи /pin-settings отправляет всем сокетам этого пользователя кадр pin_settings_changed {version} (только версия, содержимого нет; кадр лишь сигнал «проверь сервер»); клиент по кадру и при каждом (пере)подключении сам читает блок и действует: PIN сменили на другом устройстве, а это устройство открыто: тихо перешифровать локальную копию на новый PIN (без ввода старого: сессия уже разблокирована) и показать плашку «PIN обновлён»; PIN включили на другом: перешифровать и СРАЗУ вернуть это устройство на экран блокировки; PIN выключили: убрать блокировку и показать плашку. Другая вкладка того же браузера: приводим экран в соответствие с локальным хранилищем (если PIN включён вкладкой рядом, эта вкладка блокируется). Свои действия не вызывают лишних плашек (флаг). На экране блокировки постоянная подсказка: «если PIN изменили на другом устройстве, введите прежний PIN этого устройства; новый подтянется сам».
Честные пределы (объяснено владельцу): устройство, которое было закрыто или заблокировано в момент смены, новый PIN принять не может, пока не введён прежний PIN (или вход по сид-фразе): ключи на нём заперты прежним PIN, а сервер PIN и ключи не видит; держать на сервере копию ключей под новым PIN нельзя (это позволило бы подбирать PIN по утёкшей базе). Сервер, который хочет навредить, может не слать кадры: тогда устройство узнает при следующем запуске или переподключении.
### №31d (после №31e)
Конфликт 409 (ввод актуального PIN, принять новый, предложить повторить) и «Сбросить по сид-фразе» (выключить PIN или задать новый), e2e. Найденное в №31c, включить: (1) setPinSyncVersion не уменьшает версию: сброс по сид-фразе должен уметь явно обнулить (после проверки сид-фразы), иначе после законного отката сервера (восстановление базы) устройства перестанут принимать блок; (2) verifyLocal в раннере сводит все ошибки к pin_invalid, «проверка не удалась» стала показываться как «неверный PIN»: вернуть различие; (3) syncPinRef не обнуляется при ошибке restoreServerSession или отмене эффекта; (4) enableShared не проверяет откат версии сервера; (5) при неготовом контроллере действие говорит «нужна связь»; (6) плашка pin-sync-notice без внешних отступов (проверить вид).
Решения техрука по проекту (внести в PIN-SYNC-DESIGN.md при приёмке №31d): PIN устройства передаётся сверке через ref на один вызов; при включённом PIN и неизвестном PIN сверка при запуске пропускается; enable_pin из сверки не применяется при непустой очереди исходящих; смена/выключение: проверка текущего PIN локально → чтение блока → запись на сервер → локально; версия отмечается после локального применения; PIN ≤ 64 символов после NFKC; версия сверки в ключе pinSyncVersion; блок 553 байта; решающая функция живой сверки decideLivePinSync не знает PIN устройства (достаточно «включён ли PIN»).
