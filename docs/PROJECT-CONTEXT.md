## ТЕКУЩАЯ РАБОТА: проект №31 «Общий PIN» (docs/PIN-SYNC-DESIGN.md, УТВЕРЖДЁН 23 ноября)
Решения владельца: 1) новое устройство получает PIN автоматически; подсказка «не используйте PIN от банка» (добавлена в pinHint); 2) один общий PIN без исключений.
Готово: №31a сервер, №31b крипто и ядро, №31c сверка при запуске/разблокировке/входе, включение/смена/выключение через сервер, плашка pin-sync-notice, ошибка pin-error, лимит 64 символа, e2e на двух контекстах (в PR #80, ждёт Merge).
Решения техрука (внести в PIN-SYNC-DESIGN.md при приёмке №31d): (1) PIN устройства передаётся сверке через ref, читается и обнуляется один раз; если PIN на устройстве включён, а в памяти его нет, сверка пропускается; (2) enable_pin из сверки не применяется при непустой очереди исходящих; (3) смена и выключение: проверка текущего PIN локально, потом чтение блока и запись на сервер, потом локально; версия отмечается только после локального применения; (4) в №31c расхождение версии отменяет действие со словами «перезагрузите страницу»; (5) PIN не длиннее 64 символов после NFKC; (6) версия сверки в ключе pinSyncVersion, блок 553 байта.

### №31d (следующее ТЗ, после слияния №31c и ручной проверки)
Объём по проекту: конфликт 409 (ввод актуального PIN как доказательство, принять новый PIN, предложить повторить смену) и «Сбросить по сид-фразе» в профиле (ввод фразы, проверка phraseMatchesAccount, выбор «Выключить PIN» или «Задать новый»), e2e.
Найденное в №31c, включить в №31d:
1) setPinSyncVersion никогда не уменьшает версию. Если сервер откатится по законной причине (восстановление базы из копии), устройства навсегда перестанут принимать блок. Сброс по сид-фразе должен уметь явно обнулить версию (отдельная функция сброса, только после проверки сид-фразы).
2) verifyLocal в раннере сводит любые ошибки к pin_invalid: ошибка проверки PIN (PIN_KDF_FAILED) теперь показывается как «неверный PIN» вместо «проверка не удалась». Вернуть различие (пробросить причину).
3) syncPinRef не обнуляется, если restoreServerSession завершился ошибкой или эффект отменён до чтения: обнулять и там.
4) enableShared не проверяет откат (версия сервера меньше локальной): добавить проверку.
5) Если controllerRef ещё не создан, действие пользователя показывает «нужна связь»: различить, либо дождаться контроллера.
6) Плашка pin-sync-notice без внешних отступов: посмотреть на ручной проверке (360 px, тёмная тема).

## ЧТО ДЕЛАТЬ ВЛАДЕЛЬЦУ СЕЙЧАС
1. Нажать Merge в PR #80 (автослияние не включать, миграций нет). Дождаться деплоя Render, нажать F5 на сайте.
2. Ручная проверка на двух устройствах (второе: другой браузер или окно инкогнито), записать находки одним списком:
   а) устройство A: Профиль → PIN → Включить; подсказка читается, PIN включается.
   б) устройство B: войти по сид-фразе; сверху плашка «PIN обновлён…»; F5; экран PIN; PIN от A подходит.
   в) на A сменить PIN; на B нажать F5, ввести СТАРЫЙ PIN: плашка «PIN обновлён»; F5; новый PIN подходит, старый нет.
   г) на A выключить PIN; на B F5, ввести PIN: плашка «PIN отключён»; F5: экрана PIN нет.
   д) DevTools → Network → Offline: включить PIN: красная строка про связь; PIN остался выключенным.
   е) ширина 360 px и тёмная тема, если используете: плашка и красная строка читаются, вёрстка не ломается.
   Если PIN уже включён на вашем основном устройстве: после ближайшей разблокировки он сам опубликуется на сервере (это правильно); если на разных устройствах разные PIN, побеждает опубликованный первым.
3. Написать мне результат: «всё хорошо» или список находок. Потом выдам ТЗ №31d.
