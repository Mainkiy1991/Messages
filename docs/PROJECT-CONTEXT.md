## ТЕКУЩАЯ РАБОТА: №28f (дефект найден при ручной проверке №28e)
Находка владельца: после создания нового аккаунта в нём открылся ПУСТОЙ чат с ID одного из тестовых аккаунтов владельца (62d2f0dc…); после выхода, F5 и входа по той же фразе чата не было; ещё 2–3 новых аккаунта были чистыми. Владелец подумал о совпадении сид-фразы: это исключено (12 слов = 128 бит; при совпадении аккаунт показал бы свою настоящую историю, а не пустой чат).
Причина (найдена по коду, в браузере не воспроизводилась; e2e в №28f воспроизведёт): открытый чат хранится в состоянии истории браузера window.history.state = { chat: peerId } (pushState при открытии чата), при запуске приложение читает его и открывает этот чат (main.tsx, эффект запуска ChatController: historyPeer). Обычный выход confirmLogout очищает его (window.history.replaceState(null…) и chatHistoryRef.current=false), а путь «вылета» onDeviceRevoked (когда устройство завершили из другого места или выход в соседней вкладке) НЕ очищает. Владелец в завершённой вкладке сразу создал новый аккаунт без F5: новый аккаунт открыл чат прежнего аккаунта. После F5 после выхода состояние было уже чистым. Вывод: настоящая, но небольшая ошибка (данных не утекло: пустой чат, ID собеседника виден только тому же человеку в том же браузере); не регрессия №28e, а старая пропущенная очистка (путь onDeviceRevoked существует с №28c1).
№28f (ТЗ выдано 22 ноября; клиент; сложная (вход и клиентское состояние); автослияния нет; ветка fix/28f-clear-chat-history-on-revoke): вынести очистку записи истории в общую функцию и вызывать её в confirmLogout (замена двух строк), в onDeviceRevoked и в enter() (новый вход по фразе всегда начинает без открытого чата); один e2e в devices.spec.ts (три входа: аккаунт A в первой странице открывает «Избранное», вторая страница-контекст входит тем же A и нажимает «Завершить все остальные», первая страница вылетает; в ней создаётся новый аккаунт C: открытого чата и ID аккаунта A на экране нет). Числа после: crypto 53, server 152, web 276, e2e 66.
Урок для PROJECT-BASE.md (дописать при следующей правке файла): пути «выход» и «вылет по отзыву» обязаны сбрасывать одно и то же состояние; при новом ТЗ на вход или выход сверять оба пути и enter().
