# Правила для ИИ-агентов проекта Messages

Проект: открытый веб-мессенджер (React + Vite, Node.js, PostgreSQL, монорепо pnpm). Ты работаешь по ТЗ от техрука. ОС владельца: Windows (PowerShell).

## Процесс

- Перед началом: git checkout main && git pull, затем ветка из ТЗ. Доработки к открытому PR: та же ветка, сначала git fetch origin && git merge origin/main.
- В main напрямую не пушить, CI не отключать. PR открывать; автослияние включать только если в ТЗ «Автослияние: да» (gh pr merge --auto --squash; если gh недоступен, так и напиши).
- Перед каждым коммитом запускай npx prettier --write на изменённых файлах (иначе CI падает).

## Безопасность

- Никакой самописной криптографии, только libsodium / @noble и стандарты.
- Сид-фраза и приватные ключи никогда не уходят на сервер, не логируются, не попадают в URL.
- Не коммитить .env, пароли, строки подключения к БД. Не трогать packages/crypto, вход, миграции, CI без явного ТЗ.

## Экономия лимита

- Читай только нужные файлы, не изучай весь репозиторий. Без рефакторинга вне ТЗ.
- Во время работы запускай только затронутые тесты, полные один раз в конце (остальное проверит CI).
- Не выводи длинные логи, не пересказывай ТЗ. Если неясно, коротко спроси.

## Отчёт (коротко, без журнала действий)

1. Ссылка на PR и на ПОСЛЕДНИЙ запуск CI; числа тестов (crypto, server, web, e2e).
2. Список изменённых файлов.
3. Код текстом: только изменённые фрагменты, не файлы целиком. Для крипто, входа, сервера, миграций и прав доступа обязателен настоящий код. Ссылки на локальные файлы и «смотрите в PR» не принимаются.
4. Что не получилось или сделано по-своему.
